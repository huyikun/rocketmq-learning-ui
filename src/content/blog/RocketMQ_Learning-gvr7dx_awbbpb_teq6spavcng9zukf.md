## <font style="color:#2F8EF4;">产品演进历程：在技术浪潮中的成长之路</font>
<font style="color:rgba(0, 0, 0, 0.9);">早在 2018 年，Gartner 评估报告便将事件驱动模型（Event-Driven Model）列为十大战略技术趋势之一，指出事件驱动架构（EDA，Event-driven Architectures）将成为微服务架构未来的演进方向。  
</font>

<font style="color:rgba(0, 0, 0, 0.9);">随着云原生与 Serverless 技术的迅猛发展，2020 年，阿里云重磅发布事件总线 EventBridge，构建了云原生环境下的统一事件枢纽。事件总线 EventBridge 支持阿里云服务、自定义应用、SaaS 应用以标准化、中心化的方式接入，并能够以标准化的 CloudEvents 1.0 协议在这些应用之间路由事件，帮助企业轻松构建松耦合、分布式的事件集成驱动架构。</font>

<font style="color:rgba(0, 0, 0, 0.9);"></font>

**<font style="color:#2F8EF4;">自 6 月 3 日起，阿里云事件总线 EventBridge 正式商业化。</font>**<font style="color:rgba(0, 0, 0, 0.9);">历经五年迭代升级，事件总线 EventBridge 在产品功能和用户体验方面不断优化，积累了丰富的规模化生产实践经验。在数据智能化时代，事件总线 EventBridge 持续深耕企业云上事件集成，适用于各种规模和行业的事件集成场景。通过 Event 桥接各个系统，满足 AI 和企业集成等领域的各种数据集成需求，为企业提供便捷且创新的数据集成解决方案。</font><font style="color:rgba(0, 0, 0, 0.9);"></font>

## <font style="color:#2F8EF4;">产品核心特性：构建企业级事件中枢的关键</font><font style="color:rgba(0, 0, 0, 0.9);"></font>
<font style="color:rgba(0, 0, 0, 0.9);">从诞生到商业化，事件总线 EventBridge 不断优化产品核心特性，致力于定义企业级事件集成标准，为企业构建云上事件枢纽提供坚实可靠的支撑和保障。  
</font>

+ **<font style="color:rgba(0, 0, 0, 0.9);">稳定与安全：</font>**<font style="color:rgba(0, 0, 0, 0.9);">依托海量数据传输及运维经验，提供高稳定性且安全合规的企业集成服务；</font>
+ **<font style="color:rgba(0, 0, 0, 0.9);">性能与成本：</font>**<font style="color:rgba(0, 0, 0, 0.9);">提供高性能且性价比高的企业集成方案，显著降低用户数据集成成本；</font>
+ **<font style="color:rgba(0, 0, 0, 0.9);">开放与集成：</font>**<font style="color:rgba(0, 0, 0, 0.9);">提供丰富的跨产品、跨平台连接能力，促进云产品、应用程序、SaaS 服务相互集成；</font>
+ **<font style="color:rgba(0, 0, 0, 0.9);">统一事件枢纽：</font>**<font style="color:rgba(0, 0, 0, 0.9);">统一事件界面，定义事件标准，打破云产品事件孤岛；</font>
+ **<font style="color:rgba(0, 0, 0, 0.9);">事件驱动引擎：</font>**<font style="color:rgba(0, 0, 0, 0.9);">海量事件源，毫秒级触发能力，加速 EDA/Serverless 架构升级；</font>
+ **<font style="color:rgba(0, 0, 0, 0.9);">流式事件通道：</font>**<font style="color:rgba(0, 0, 0, 0.9);">事件流提供轻量、实时、端到端的流式数据处理，对源端产生的事件进行实时抽取、转换和分析并加载至目标端。</font>

## <font style="color:#2F8EF4;">多元应用场景：覆盖各类企业事件集成场景</font>
### <font style="color:rgba(0, 0, 0, 0.9);">EDA 事件驱动场景</font><font style="color:rgba(0, 0, 0, 0.9);"></font>
<font style="color:rgba(0, 0, 0, 0.9);">事件总线 EventBridge 通过事件连接应用程序、云服务和 Serverless 服务，构建事件驱动架构（EDA，Event-driven Architectures），实现应用与应用、应用与云服务之间的高效连接。</font>

### <font style="color:rgba(0, 0, 0, 0.9);">流式 ETL 场景</font><font style="color:rgba(0, 0, 0, 0.9);"></font>
<font style="color:rgba(0, 0, 0, 0.9);">在企业集成场景中，事件总线 EventBridge 可以作为流式数据管道，提供基础的过滤与转换功能，支持不同数据仓库、数据处理程序、数据分析与处理系统之间的数据同步和跨地域备份，连接不同系统与服务。</font>

### <font style="color:rgba(0, 0, 0, 0.9);">AI 数据集成场景</font>
<font style="color:rgba(0, 0, 0, 0.9);">事件总线 EventBridge 提供非结构化数据到结构化数据的链路集成，可处理多种数据源，如关系型数据库、API 数据、文件、ODPS 等，并支持将数据向量化后存储至向量数据库或其他数仓，同时支持数据清洗、转换和规范化。为 RAG 和模型数据准备等场景，提供一站式数据集成服务。</font>

### <font style="color:rgba(0, 0, 0, 0.9);">统一事件通知服务</font><font style="color:rgba(0, 0, 0, 0.9);"></font>
<font style="color:rgba(0, 0, 0, 0.9);">事件总线 EventBridge 提供丰富的云产品事件源与事件的全生命周期管理工具，用户可以直接监听云产品产生的数据，并上报至监控和通知等下游服务，实现高效的事件管理和响应。</font>

### <font style="color:#000000;">事件流计费说明</font>
<font style="color:rgba(0, 0, 0, 0.9);">事件流</font><sup><font style="color:rgba(0, 0, 0, 0.9);">【2】</font></sup><font style="color:rgba(0, 0, 0, 0.9);">是端到端的流式事件通道，适用于端到端的流式数据处理场景。事件流属于收费服务，并支持按事件量计费和按 CU 额度计费，这两种计费</font><sup><font style="color:rgba(0, 0, 0, 0.9);">【3】</font></sup><font style="color:rgba(0, 0, 0, 0.9);">方式你只需二选一即可。</font>

| <font style="color:rgba(0, 0, 0, 0.9);">计费项</font> | <font style="color:rgba(0, 0, 0, 0.9);">计费单价</font> |

<font style="color:rgba(0, 0, 0, 0.9);">  
</font>

+ <font style="color:rgba(0, 0, 0, 0.9);">事件量：事件流拉取上游数据源的事件总量。每个 64KB 大小的事件计为 1 个事件。计算公式：事件量（向上取整）=单个事件大小/64KB。例如：批量投递了 300KB 的单个事件，则按照 5 个事件进行计费。若事件发生重试，则按照配置的重试规则每次重试计为 1 个事件。</font>
+ <font style="color:rgba(0, 0, 0, 0.9);">空置资源占用量：若单个事件流在一个月内没有任何数据流入将会按照计费标准收取空置资源占用费，空置资源占用费将在有数据流入或者删除该事件流后取消计费。</font>

#### **<font style="color:#2F8EF4;">按 CU 配额计费</font>**
##### **<font style="color:rgba(0, 0, 0, 0.9);">名词介绍</font>**
<font style="color:rgba(0, 0, 0, 0.9);">CU 配额： CU（Capacity Unit）是事件总线任务的容量单位。若采用 CU 规格计费，则每个任务必须至少分配 1CU 作为最小配额。亦可在任务创建时指定允许弹性的最大 CU 规格和最小 CU 规格。</font>
